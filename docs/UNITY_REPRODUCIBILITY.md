# Unity project reproducibility — P0/P1 evidence

## Required committed evidence

- `unity/Packages/packages-lock.json`: resolved **by Unity Package Manager**, not authored by hand.
- `unity/ProjectSettings/ProjectSettings.asset`: produced **by Unity Editor 6000.3.25f1**, not fabricated from a template.
- `unity/ProjectSettings/ProjectVersion.txt`: exact editor pin `6000.3.25f1`.

The packages-lock and PlayerSettings files are absent from the initial source baseline. Until the exact two files have been generated by Unity, reviewed and committed, strict reproducibility and `main` promotion remain blocked.

The local package directories are intentionally not committed. The bootstrap scripts must install them before Unity resolves `manifest.json`. Bootstrap patches are part of the build inputs. Do not silently upgrade or substitute different upstream package versions.

## CI capture on a clean checkout

1. Branch `fix/unity-reproducibility-baseline` triggers `.github/workflows/capture-unity-reproducibility.yml`. Its checkout excludes `Library/`; pinned bootstrap scripts run in order.
2. GameCI opens Unity 6000.3.25f1 and builds the integrated Windows alpha using the same production Unity entrypoint. This is **real Unity package resolution**, not JSON templating.
3. `tools/validate-unity-reproducibility.py` checks editor version, pinned direct dependencies, lock graph (including Git commit hashes), and Unity PlayerSettings serialization. `tools/validate-repository-structure.py --strict-reproducibility` must also pass.
4. The exact generated files are uploaded as evidence and committed **only** to the capture branch, leaving `develop` untouched until the PR is reviewed. If Unity does not generate either file, the workflow fails without committing a substitute.
5. Review PR diff, especially PlayerSettings graphics/standalone settings, and then merge into `develop`.
6. Run strict repository reproducibility validation on a **second clean checkout**. Windows and macOS standalone and OBS verification remain separate test gates; a Unity project import does not prove desktop runtime quality.

## Local equivalent

```bash
bash tools/bootstrap-mediapipe.sh
bash tools/bootstrap-ui-fonts.sh
bash tools/bootstrap-ultraleap.sh
bash tools/bootstrap-uniwinc.sh
# Open unity/ in Unity 6000.3.25f1, allow Package Manager resolution.
python3 tools/validate-unity-reproducibility.py
python3 tools/validate-repository-structure.py --strict-reproducibility
```

Use the existing PowerShell MediaPipe bootstrap on Windows, then ensure the local patched Ultraleap/UniWinC packages are present using the supported Bash bootstrap environment.

## Remaining evidence boundary

Generated `packages-lock.json` and `ProjectSettings.asset` prove reproducible dependency selection and editor configuration, not bit-identical standalone archives or runtime hardware correctness. Mac Apple Silicon/Windows GPU, native transparency, VRM load, tracking, OBS and performance evidence stay deferred until measured.
